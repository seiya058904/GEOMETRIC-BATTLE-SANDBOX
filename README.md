# GEOBATTLE · 几何战争沙盒

一款可以离线游玩的 2D 俯视自动战争沙盒。自由混编 36 种预设兵种，排好军阵后观察真实的移动、碰撞、武器弹道、技能、伤害和胜负。没有预算约束；所有攻击和负面技能效果均禁止作用于友军。

## 立即开始

1. **先解压整个 ZIP。** 不要直接在压缩包预览器中打开文件。
2. 双击根目录的 **`GEOBATTLE-OFFLINE.html`**，用浏览器打开。
3. 首屏已经布好红蓝各 40 个单位。点击右上角 **开始战斗**，即可观察第一场混编战争。
4. 战斗中可暂停、调整倍速、平移缩放和查看单位。点击 **返回布阵** 恢复开战前的完整军阵。

这个单文件包含完整 JavaScript 和样式，没有 CDN、在线字体、图片服务器、登录或游戏后端依赖。不需要安装 Node.js，也不需要运行开发服务器。游戏内所有单位和特效都是程序化几何图形。

### 使用本地地址打开生产版本

如果浏览器对直接打开文件的存档行为有限制，可以使用本地服务器。安装 Node.js 22 或更高版本，在解压后的项目目录打开终端：

```bash
node scripts/serve.mjs --dist
```

然后打开 `http://127.0.0.1:4178`。此命令只使用 Node 内置模块，运行随包提供的 `dist/`，无需安装 npm 依赖。关闭终端或按 `Ctrl+C` 停止服务器。

## 从源码开发和构建

Windows 可在项目文件夹地址栏输入 `cmd` 打开命令提示符；macOS/Linux 可在终端切换到项目目录。

```bash
npm ci
npm run dev
```

打开 `http://127.0.0.1:4178`。修改源码后刷新页面即可；开发服务器不包含热更新。

```bash
npm run check
npm test
npm run build
npm run preview
```

| 命令 | 用途 |
| --- | --- |
| `npm ci` | 按锁文件安装构建依赖；首次安装需要可访问 npm 或已有缓存 |
| `npm run dev` | 从 `src/` 提供开发页面 |
| `npm run check` | 对源码、脚本和测试执行 JavaScript 语法检查 |
| `npm test` | 运行纯模拟、编辑器、持久化和输入适配测试 |
| `npm run build` | 重建 `dist/` 和 `GEOBATTLE-OFFLINE.html` |
| `npm run preview` | 通过本地服务器预览 `dist/` |
| `npm run test:browser` | 执行真实 Chromium 浏览器操作验收；需要额外安装 Playwright |
| `npm run test:offline` | 禁用浏览器网络，验证随包单 HTML 的加载与真实战斗 |
| `npm run test:performance` | 执行真实浏览器规模测试并写出性能证据 |

需要改变端口时，可运行 `npm run dev -- --port 4180`。服务器只监听当前电脑的 `127.0.0.1`。

## 排兵布阵

先选择红队或蓝队，再从左侧兵种库选择单位。可以按六大分类筛选，或搜索名称、角色和技能描述。所有兵种一开始全部开放，双方都能使用全部种类。

| 工具或操作 | 用法 |
| --- | --- |
| 放置 | 点击空位放置一个单位；触摸屏在单指抬起时提交 |
| 笔刷 | 按住拖动，按路径间距连续放置；一次拖动作为一次撤销操作 |
| 直线 | 从起点拖到终点，松开后生成等距直线军阵 |
| 矩阵 | 拖出矩形范围，松开后生成网格军阵 |
| 选择 | 框选当前阵营；点击已有单位后拖动可移动整个选区；Shift 可追加选择 |
| 擦除 | 拖动删除当前阵营的单位，另一阵营不受影响 |
| 镜头 | 拖动平移；鼠标右键、中键或 Alt 拖动也可平移 |
| 旋转 | 在右侧详情的“军阵编辑”中点击 −15° 或 +15°，绕选区中心旋转 |
| 复制、粘贴 | 复制选区后点击粘贴，再在战场点击落点；可以先切队，再粘贴到当前阵营 |
| 镜像给对方 | 将选区左右镜像到另一阵营，保留相应朝向关系 |
| 交换阵营 | 将双方整体互换阵营，位置与面向保持不变 |
| 清空、恢复、整场镜像 | 打开“军阵”，使用其中的战场操作；布阵变更均可撤销 |

右侧详情可以设置新部署单位的面向角度和紧凑/标准/宽松/分散间距。参考成本只用于比较兵种和军阵，不会扣除金币或限制部署。将鼠标停留在顶栏队伍人数上可以查看该队总参考成本。

单位必须完整处于 2400 × 1350 的战场边界内，初始位置会检查实际半径和间隔。无效点显示禁止轮廓；批量工具跳过无效点并报告成功与跳过数量。移动、旋转等整体操作遇到非法位置时完整拒绝，不会偷偷丢掉部分单位。

浅色部署区域只是视图建议，双方始终能部署到任意合法空位。“自由部署”会隐藏该建议区。没有各队名额限制；保护上限为全场 **1200 个活动单位**，包含召唤物。达到上限后拒绝新增，已有单位不会被删除，死亡腾出空间后可以继续召唤。

### 随机大战

点击左下角“随机大战”，选择小型 20、普通 80、大型 300 或混沌 600 个单位，并填写或更换种子。数字是双方合计。生成后仍可自由编辑，也可以撤销。相同生成种子、相同规模和同一构建会产生相同军阵。

## 观察战斗

红蓝双方各至少有一个单位时才能开战。进入战斗后，布阵操作锁定，玩家只能观察和控制时间、相机与视听设置。

- **时间：** 支持 0.25×、0.5×、1×、2×、4×；模拟始终按固定 `1/60` 秒推进。设备算力不足时实际速度可能低于请求值，可在设置中打开性能信息查看。
- **暂停：** 冻结单位、冷却、弹丸、伤害和特效；暂停时仍可操作相机。页面进入后台会自动暂停。
- **相机：** 滚轮以鼠标位置为中心缩放，拖动平移；“适配军阵”框住当前单位，“全图”恢复战场视图。
- **单位观察：** 点击任一存活单位，查看生命、目标、AI 状态、攻击/技能冷却、击杀、伤害和治疗。可以跟随该单位，平移或缩放会取消跟随。
- **设置：** 可改变画质、生命条、网格、轻微震动、自动取景、性能信息、静音和音量。降低画质只影响绘制细节，不改变战斗规则。
- **声音：** 使用本地 Web Audio 合成短音效；第一次点击交互时解锁音频。静音与音量设置会保存在当前浏览器。

### 胜负与重赛

一方所有有效单位被消灭后判负；召唤物仍可延续战斗，已发出的弹道、残留燃烧与延迟技能会完成结算。同一个模拟 tick 中双方同时消灭对方判平局。

没有交战推进或有效战局变化持续 15 秒后，AI 启用主动接近保底；继续 20 秒仍未恢复有效战局则判僵局平局。最长模拟时间为 240 秒，超时同样明确判平局。

战报包含真实事件累计的初始人数、幸存、阵亡、召唤、伤害、治疗、最高伤害单位、最多击杀单位与各兵种统计。

- **同种子复现：** 使用这一场开战前的快照和原种子重演。
- **新种子重赛：** 保留同一初始军阵，改变随机序列。
- **返回布阵：** 恢复开战前的兵种、位置、生命初始化条件与朝向，不把尸体或召唤物写回编辑器。

确定性验证覆盖同一构建中的固定种子、不同 tick 分批与视觉预算。不同浏览器、CPU 架构之间不承诺浮点状态逐字节一致。新种子不保证一定改变胜负：悬殊兵力或纯确定性场景可能得到相同结果。

## 手机和平板

窄屏下左侧兵种库和右侧详情折叠为抽屉。点击画布下方“兵种”选择单位，点击“详情”打开部署参数与军阵编辑。底部保留七种工具和随机大战、撤销、重做入口。

单指使用当前工具，双指缩放和平移。选择“镜头”工具后可用单指平移。复制、旋转、镜像、保存等重要功能均有按钮，不依赖键盘。

## 保存与 JSON 文件

编辑后的布阵会自动写入当前浏览器的 `localStorage`，刷新后恢复。打开“军阵”可保存具名预设、读取、删除以及导入导出 JSON；同名保存会更新已有预设。保存的是战前布阵，不是战斗进行到一半的状态。

| 数据 | 存储键 |
| --- | --- |
| 最近一次布阵 | `geobattle.autosave.v1` |
| 具名军阵预设 | `geobattle.presets.v1` |
| 视听设置 | `geobattle.settings.v1` |

存档与当前浏览器、站点地址绑定，不会自动同步到其他设备。直接打开 HTML 时，不同浏览器对文件存储的策略可能不同。导出 JSON 是迁移和长期备份军阵的方式；存储被禁用、损坏或写满时会显示提示，游戏仍可继续使用。

格式版本为 `schemaVersion: 1`，包含无符号 32 位 `seed` 和 `units` 数组。每个单位保存正整数 ID、兵种 ID、红/蓝阵营、世界坐标与弧度角。合法的最小对战示例：

```json
{
  "schemaVersion": 1,
  "seed": 314159,
  "units": [
    { "id": 1, "type": "swordsman", "team": "red", "x": 1000, "y": 675, "angle": 0 },
    { "id": 2, "type": "swordsman", "team": "blue", "x": 1400, "y": 675, "angle": 3.141592653589793 }
  ]
}
```

导入上限 2 MiB、1200 单位。未知版本或兵种、重复 ID、越界、重叠、非有限数值与损坏 JSON 会被拒绝，当前军阵保留。空军阵可以保存和导入，仍需双方各部署至少一个单位才能开始。

## 工程结构

本实现采用 **原生 JavaScript ESM + JSDoc、Canvas 2D、Web Audio、Node 内置测试和 esbuild**。这是对推荐 React/TypeScript/Vite 技术栈的明确调整：保留模块边界、模拟与界面隔离、固定时间步，并减少运行依赖，提供可直接打开的离线单 HTML。

| 路径 | 内容 |
| --- | --- |
| `src/data/units.js` | 36 兵种基础数值及召唤物定义 |
| `src/sim/` | 固定步模拟、AI、技能、集中战斗规则、弹道、物理、空间索引与种子 RNG |
| `src/editor/` | 部署合法性、批量布阵、选择变换、100 步历史、默认和随机军阵 |
| `src/persistence/` | JSON 校验、自动保存和具名预设 |
| `src/render/` | 相机、真实几何造型、Canvas 渲染、LOD、视野裁剪与合成音频 |
| `src/ui/` | 目录、详情、对话框和 SVG 控件 |
| `src/controller.js` / `src/input.js` | 唯一主循环、状态切换与指针/触摸/键盘适配 |
| `tests/` | 规则、编辑器、输入、浏览器流程与性能测试 |
| `scripts/` | 无框架本地服务器、构建与语法检查 |
| `design/` | 两张实际 AI 生成参考图、提示词和视觉采用说明 |
| `evidence/` | 测试原始日志、JSON 数据和真实浏览器截图 |
| `docs/GAME-DESIGN.md` | 实际战斗、技能、胜负、随机性和模拟边界 |
| `docs/UNIT-ROSTER.md` | 36 兵种实际属性、攻击、能力与平衡解释 |
| `docs/QA-AND-PERFORMANCE-REPORT.md` | 最终验收、修复、环境、实测性能和已知限制 |
| `dist/` / `GEOBATTLE-OFFLINE.html` | 随包提供的生产构建 |

## 复现浏览器测试

常规开发环境可额外安装测试工具：

```bash
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install chromium
npm run test:browser
npm run test:offline
npm run test:performance
```

测试脚本会启动和关闭自己的本地服务器。也可设置 `PLAYWRIGHT_MODULE` 指向准备好的 Playwright 模块，`PLAYWRIGHT_EXECUTABLE` 指向浏览器可执行文件；`GEOBATTLE_TEST_URL` 可调整测试端口。设置 `GEOBATTLE_TEST_DIST=1` 验证生产构建，设置 `GEOBATTLE_EXTERNAL_SERVER=1` 使用已自行启动的服务器。

性能脚本支持 `PERF_SCENE` 选择单一规模、`PERF_SECONDS` 调整采样时间。设置 `GEOBATTLE_LONGRUN=1` 运行连续战斗和重赛验收；同时设置 `PERF_SCENE=none` 可只跑长测。长测默认请求 4×，需要至少 180 秒真实运行、累计 180 秒模拟和首局之外至少 3 次自然结束的重赛；任何门禁不足都会报告失败。它使用实际 CDP 堆读数，保留长帧，不以粗化内存显示或单次堆差值宣称“无泄漏”。具体最终命令、版本和采样口径见 QA 报告。性能数字只对报告中的环境成立，纯模拟每 tick 耗时不能替代浏览器 FPS。

## 本次验收与性能

规则、编辑、持久化、输入与网格测试 **194 / 194** 通过。完整浏览器交互套件此前 **68 / 68** 通过；最终构建另做六视口复核 **20 / 20**、桌面/手机与战中详情检查 **6 / 6**、单 HTML 断网检查 **3 / 3**。最终六视口的 18 张截图均已保存并逐一检查可见战场。

最终可见画布构建在无头 Chromium 153、SwiftShader、1920 × 1080 / DPR 1 的本次测量中，**没有达到任务书的 60 / 30 FPS 目标**。以下是每场约 12 秒、保留全部原始 RAF 间隔的结果；请求速度均为 1×：

| 初始规模 | 平均 FPS | 实际模拟速度 |
| --- | ---: | ---: |
| 1 对 1 | 12.28 | 0.589× |
| 10 对 10 | 12.63 | 0.682× |
| 100 对 100 | 11.28 | 0.640× |
| 300 对 300 | 10.92 | 0.710× |
| 500 对 500 | 12.49 | 0.868× |
| 600 对 600 | 12.05 | 0.636× |
| 极端特效，120 对 120 | 12.61 | 0.761× |

这些场景全部实际推进且数值有限，但不能据此保证流畅。性能脚本的 `passed` 表示采样、推进和有限性检查通过，**不表示帧率目标通过**。主画布采用常规呈现，并与静态图块一起请求适合软件绘制的上下文；中间版本曾出现截图战场空白，已修复并保留诊断证据，不使用那一版本较快的数字作为最终性能。

同一最终构建连续运行 **180.10 秒墙钟、516.38 秒模拟**，请求 4× / auto，实际约 **2.867×**；自然完成 **26 局**，其中 **25 局是完成的重赛**，同种子完整结果一致，无记录到的模拟异常。12 段 CDP 堆采样完整；未强制回收，末值比起点高约 15.05 MB，因此不宣称已经排除内存泄漏。详见 [QA 与性能报告](docs/QA-AND-PERFORMANCE-REPORT.md)、[最终规模原始数据](evidence/browser-performance.json) 和 [持续运行原始数据](evidence/browser-longrun.json)。

## 已知边界

- 实测浏览器为报告中注明的 Chromium；Windows 实体 GPU、Firefox、Safari 和真实 Android/iOS 设备尚未独立验收。
- 1200 是保护上限，不是每种设备都能流畅承载的推荐人数。默认 80 人可直接体验；大场面可打开性能信息并选择低画质。详细的真实帧率与长帧记录见 QA 报告。
- 碰撞采用有限迭代的软圆形分离与冲量，密集集团可能短暂压挤；不提供通用刚体或复杂路径寻路精度。
- 平衡以沙盒差异和技能表现为目标，没有宣称 36 兵种已达到竞技公平。全部基础数值与具体技能取舍可在兵种文档中审阅。
- Canvas 战场主要面向视觉与指针操作，按钮和表单具备原生语义及焦点提示，但没有实现可替代整片战场的屏幕阅读器交互模式。

# GEOBATTLE · 实际游戏规则与模拟设计

本文描述交付源码实际执行的规则。所有世界坐标、速度、冷却、状态和伤害均由模拟引擎计算；Canvas 渲染只读取状态。

## 1. 自由沙盒与战斗闭环

战场是 2400 × 1350 的连续空旷平面。没有地形、障碍、阵营购买预算、文明限制或时代克制。36 种预设兵种全部可以自由混编，COST 只表示参考成本。红蓝双方各至少一个合法单位才可开战。

编辑态的单体、笔刷、直线、矩形、框选、移动、旋转、复制、镜像、删除与撤销操作产生编队数据。开战复制编队并冻结初始快照。战斗中的相机、时间控制和观察不改变初始部署；返回布阵恢复初始兵种、生命之外的部署属性、位置与方向，而不是战后的残血实体。

V2 准备阶段统一按世界坐标确定队伍：红方 `x+radius+2≤1200`，蓝方 `x−radius−2≥1200`，世界边界仍按完整半径。单笔部署锁队，直线/矩阵非法候选跳过并汇报；移动/旋转/粘贴整组原子校验，混合队伍不能零散变队；镜像和对调同步位置、队伍、朝向。右键按实际命中删两侧，触摸显式部署/擦除/平移，多指取消事务。旧跨区存档先只读预览并保留原文，明确迁移副本后才可开始。战斗中的追击、冲锋、闪现、召唤不受半场限制；36 兵种数值与所有模拟规则保持不变。详见 `V2-MIGRATION.md` 与 `V2-UX-AND-INTERACTION.md`。

活动实体总上限为 1200，包含红蓝双方和所有召唤物。上限不是每队配额，也不是保证任意设备可保持 60 FPS 的承诺。大型单位因身体半径需要更大的合法部署空间；即使没有达到人数上限，也可能需要更大空位。V2 性能证据见 `V2-PERFORMANCE-INVESTIGATION.md`；`QA-AND-PERFORMANCE-REPORT.md` 与原 `evidence/simulation-performance.json` 保留为 V1 历史证据。

## 2. 固定模拟时钟与复现

引擎只通过 `Simulation.step()` 前进，每次严格推进 1/60 模拟秒。它不创建 RAF、定时器或墙上时钟任务。主界面统一安排步进，0.25×、0.5×、1×、2×、4× 只改变每段现实时间执行多少完整 tick。暂停时单位、投射物、技能和特效年龄全部冻结。

每场战斗使用显式 uint32 种子和 Mulberry32。实体按数字 ID 稳定排序；空间网格、命中排序和同 tick 事件具有稳定顺序。模拟不调用 `Math.random()`。同编队、同种子、同版本的确定性验证覆盖不同 tick 批量和不同视觉预算。没有承诺不同浏览器/CPU 浮点实现之间逐字节一致。

独立 API：

```js
import { Simulation } from '../src/sim/engine.js';
const sim = new Simulation({ schemaVersion: 1, seed: 42, units: [
  { id: 1, type: 'swordsman', team: 'red', x: 900, y: 675, angle: 0 },
  { id: 2, type: 'peasant', team: 'blue', x: 1350, y: 675, angle: Math.PI },
] });
sim.step();
console.log(sim.units, sim.projectiles, sim.summary());
```

`result` 在进行中为 `null`。`summary().winner` 在进行中也为 `null`；结束后才是 `red`、`blue` 或 `draw`。`snapshot()` 是可 JSON 序列化的确定性核心观察快照，不是任意时间轴读档格式。

## 3. AI 与运动

单位选择目标、接近、重新定位、攻击、施法、短暂后撤、硬直、倒地、恢复和死亡。常规 AI 每约 0.24～0.34 秒分散决策，目标至少锁定约 0.65 秒；目标死亡后立即重新搜索。移动、受击和弹道仍每 tick 更新。

80 单位宽的空间网格用于寻敌、局部避让、身体碰撞、范围技能和弹道候选筛选。最近邻通过网格环扩张搜索；兵种偏好只对有限局部候选评分，不执行每帧全体单位两两寻敌。

- 近战接近实际武器作用距离，攻击需要转向和前摇。
- 盾兵面向当前主要威胁；长枪兵偏好冲锋敌人。
- 野狼偏好残血、脆弱、孤立目标；迅猛龙、骑兵和外星人偏好可绕袭的后排。
- 巨人、坦克、火箭兵、火法师和巨龙会考虑附近敌群密度。
- 射手仅在近距离、远离边界且后撤冷却结束时后撤，最长约 0.6 秒、最多 75 世界单位，随后有约 4.8 秒冷却。
- 无人机在射程内侧移，飞碟/无人机仍然与地面单位使用同一受击规则。
- 治疗师在 445 单位以内找受伤友军，综合生命比例和距离选择目标；没有患者时等待或跟进。
- 检测局部移动受阻后侧向重新定位；边界会修正移动方向并限制坐标。

普通移动使用加速度与转向速度。坦克转向较慢且炮塔独立瞄准；悬浮机械保留更多惯性。近邻圆形身体按质量倒数分配穿透分离，巨物更难被小单位推开。友军之间只有无害的软分离。

## 4. 攻击与伤害

普通攻击有前摇、命中与恢复。剑/巨锤/象牙使用朝向扇形，长枪使用狭窄线段，短棒/拳/撕咬使用实际朝向与距离判定。攻击不能仅因为两个图形接触就不断扣血。

箭、子弹、散弹、火箭、炮弹、魔法弹、能量弹、卡牌和回旋镖具有位置、速度、飞行时间和有限寿命。命中使用前后两个模拟位置之间的线段与敌方圆形碰撞体扫掠检测。友军身体既不受伤，也不消耗或提前引爆己方弹丸。

默认护甲公式：

```text
有效护甲 = max(0, 防御护甲 - 攻击穿甲)
直接伤害 = max(1, 原始伤害 × 100 / (100 + 有效护甲) × 正面盾牌倍率)
```

狙击穿甲 24；激光穿甲 12。持续燃烧绕过护甲与盾牌，独立以每秒 5 生命结算。普通命中只有 1 点下限，燃烧使用自身短间隔的实际伤害量，避免 tick 伤害被最小伤害放大。

盾兵正面 120° 减伤；直接弹道和范围爆炸的远程伤害 ×0.4，普通近战 ×0.7。弹道以到达前的实际位置判定来向，爆炸以真实爆心判定来向，背后没有格挡。因此施法者的位置不替代爆心位置。盾牌降低伤害但不是完全免疫。

火箭、炮弹、火球等范围爆炸可按离爆心的距离衰减。击退由攻击的明示冲量和目标质量决定，速度有有限上限并逐步衰减。受击后碰撞其他敌人的连锁小额伤害归属最初冲击者，仍经过统一阵营检查。

## 5. 绝对友军免伤

所有负面作用都通过 `canApplyHostileEffect(source, target)`。来源与目标必须是有效红/蓝队，目标存活，双方阵营不同；召唤物的主人阵营还必须与其自身阵营一致。没有友军误伤开关。

集中规则覆盖直接伤害、穿透、爆炸、持续燃烧、减速、眩晕、恐惧、倒地、冲锋制动、拉拽、冲量、诱饵目标转移和来源明确的连锁冲撞。治疗只允许对其他存活友军，不允许自疗、复活或治疗诱饵。

来源死亡不会使已经发出的弹丸、正在生效的燃烧或已经形成的延迟能量场失去伤害归属。死亡实体不会开始新攻击或新技能，未完成近战前摇和第二拳会取消。

## 6. 状态、控制与特殊能力边界

- 燃烧：最长 4 秒，基础每秒 5 HP，每 0.25 秒累计结算；刷新持续时间，不叠加无限燃烧层数。
- 冰冻表现为减速：最多 3 秒、移速 ×0.6；多次命中不会叠成 0 移速。
- 眩晕：单个连续控制窗口最多 0.65 秒。
- 倒地：单个连续窗口最多 0.8 秒。
- 恐惧：单个连续窗口最多 1.4 秒，只改变移动/转向，不改变阵营。
- 硬控结束后有短暂恢复保护：眩晕、倒地各 0.35 秒，恐惧 0.7 秒。反复刷新同一状态不能无限延长一个控制窗口。
- 骑兵/犀牛需要至少约 72 单位加速距离、实际速度超过常规速度的 82% 才能准备冲锋；站立攻击无法无限触发冲锋。
- 骑兵首撞后进入 5.5 秒冷却。犀牛首撞后沿方向维持 0.42 秒冲刺，可命中多个不同敌人，每次冲刺同一敌人仅一次。
- 坦克需要约 52 单位行驶距离和至少 45 单位/秒的移动速度才可准备碾压，命中后冷却 3.8 秒。
- 闪现的位移最多 220，优先敌人侧后方空位；必须通过边界和真实身体检查。没有空位时尝试短侧移，失败不会产生无敌或非法位置。
- 迅猛龙与弹簧怪使用高速运动轨迹，身体/技能命中仍检查扫掠或实际落点，不靠看不见的全场伤害。

## 7. 召唤、诱饵与回收

骷髅和小丑诱饵是技能衍生实体，不在手动部署的 36 兵种目录里。

死灵法师每 7 秒尝试生成至多 2 只骷髅，每位主人最多同时 8 只。骷髅最长存活 22 秒。小丑每 9 秒尝试生成一个诱饵，每位主人同时至多 1 个，诱饵寿命 6 秒、HP 62，没有攻击能力且不能被治疗。诱饵可以吸引附近敌人转移目标，并被敌人正常攻击和摧毁。

召唤点必须是合法空位。所有召唤共同受 1200 活动实体上限约束；达到上限时本次召唤失败并设置容量反馈，原有单位的规则与生命不会被修改。没有合法空位时死灵法师稍后重试。

主人死亡后已存在的骷髅继续按剩余寿命作战。召唤物的伤害、治疗、击杀计入主人及其兵种统计，团队累计只计算一次。其自身详情保留个人贡献，避免匿名攻击。

尸体不参与寻敌、弹丸碰撞或部署空位判定，约 2.4 秒后从活动渲染列表回收。初始单位的战绩记录最多 1200 份，仍可供战后查看；已过期的召唤对象从实体索引释放。投射物有有限飞行寿命且复用记录；视觉特效最多 850 个，视觉裁减不调用战斗 RNG 或改变命中。

## 8. 同 tick 结算、胜负与僵局

同一 tick 先收集有效攻击，统一结算伤害，再标记死亡；死亡自爆产生的事件在同一 tick 内继续结算，最后才判胜。双方最后有效实体同 tick 死亡，结果为平局，不偏向红队或较小 ID。

普通胜利以一方所有有效战斗实体，包括骷髅和诱饵，被消灭为条件。若败方尚有已发出的弹丸、敌方身上的燃烧或已形成的延迟攻击场，则短暂完成这些既有作用的结算；它们可能导致同归于尽。这不是让死亡来源重新施法。

连续 15 秒没有有效生命变化，也没有更近的交战距离时，强制停止过度后撤并主动交战。此后若连续无进展总时长达到 35 秒，则判僵局平局并说明原因。普通绕圈或来回移动不会刷新进度：推进使用历史最小敌我距离的下降，而非任何位移。无论如何，240 模拟秒为全局时限，超时平局，不使用随机胜负。

## 9. 统计口径

初始单位与召唤物单独计数：

```text
初始人数 = 剩余初始人数 + 初始阵亡人数
累计召唤数 = 在场召唤数 + 已阵亡/到期召唤数
在场有效数 = 剩余初始人数 + 在场召唤数
```

伤害按实际扣除的生命累计，不把过量伤害算作真实伤害。治疗按实际恢复量累计。兵种表汇总和团队统计使用同一事件来源；排行榜从真实初始单位的贡献记录计算，无伤害/无击杀时显示无。自然寿命到期与自爆消耗不会伪造一次敌方击杀。

## 10. 实施取舍与验证范围

基础 HP、速度、半径、ATK、攻击间隔、射程、护甲和 COST 沿任务书表格保留；补充的是质量、转向、技能几何、冲量、前摇和状态边界。大猩猩第二拳为基础 ATK 的 70%；回旋镖回程为 70%；狙击第二目标为 75%。这些是多段攻击明确规则，没有基于某场演示胜负的隐藏加成。

技术采用原生 JavaScript ESM、Canvas 2D 与 Node 内置测试，没有 React/Vite 运行依赖，也没有服务器端战斗逻辑。技能和 AI 是轻量的战术近似，不使用复杂寻路或通用刚体引擎。数值旨在产生有解释的强弱差异，未宣称达到竞技平衡。

纯模拟测试与实际浏览器验收分开记录。Node 步进耗时不是浏览器 FPS；性能硬件、视口、渲染条件和未验证的真实设备范围以验收报告为准。

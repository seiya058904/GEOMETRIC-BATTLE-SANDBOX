## 1. 验收范围与证据使用原则

游戏采用原生 JavaScript ESM + JSDoc、Canvas 2D、Web Audio、Node 内置测试和 esbuild。模拟、兵种数据、编辑器、持久化、输入、渲染、音频与界面分别成模块；不依赖游戏后端、账号、CDN 或在线素材。它实现 2400 × 1350 空旷二维战场、36 种预设单位、红蓝自由混编和固定 `1/60` 秒自动战斗。实际规则见 [GAME-DESIGN.md](GAME-DESIGN.md)，全兵种数值及技能见 [UNIT-ROSTER.md](UNIT-ROSTER.md)。

不同证据回答不同问题：

| 证据层 | 能支持的结论 | 不能据此宣称的结论 |
| --- | --- | --- |
| Node 规则、编辑器和输入测试 | 给定条件下的判定、状态变化、数据边界、确定性与事务正确性 | 真机画质、实际扬声器听感、浏览器 FPS |
| Node 纯模拟基准 | 指定编队、步数和环境中的 CPU 步进成本与有限状态 | Canvas 绘制性能、网页流畅度、用户电脑能达到的 FPS |
| 真实 Chromium 操作 | 点击、指针、触摸事件、自然 RAF 战斗、存档和状态闭环实际工作 | Firefox/Safari/真实 Android/iOS 已兼容 |
| 六视口截图与视觉审查 | 指定 CSS 尺寸下的布局、字形、阵营辨识和界面可见性 | 实体 4K 显示器、高 DPR 手机或触摸硬件实测 |
| 真实浏览器性能采样 | 该软件渲染环境中实际 RAF 间隔、步进 CPU、绘制 CPU 和模拟推进速度 | 实体 GPU 表现，或以统计平均掩盖长帧 |
| CDP 堆检查点 | 当时的 JavaScript 堆使用量、总量及其变化 | 浏览器进程全部内存、GPU 内存、严格的无泄漏证明 |

### 2.2 从工程根复现

以下为可直接复现相同范围的命令。`npm ci` 需要可用 npm 缓存或首次网络安装；游玩随包生产文件无需安装依赖。

```bash
npm ci
npm run check
npm test
npm run build
node scripts/serve.mjs --dist
```

普通测试环境安装额外的浏览器 QA 工具：

```bash
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install chromium
```

功能验收可以整套执行，也可按模块分开。以下环境变量写法适用于 Bash；Windows PowerShell 可通过 `$env:变量名='值'` 设置同名变量后再执行 Node 命令。

```bash
node tests/browser.mjs

GEOBATTLE_TEST_SECTION=editor node tests/browser.mjs
GEOBATTLE_TEST_SECTION=storage node tests/browser.mjs
GEOBATTLE_TEST_SECTION=battle node tests/browser.mjs
GEOBATTLE_TEST_SECTION=replay node tests/browser.mjs
GEOBATTLE_TEST_SECTION=responsive node tests/browser.mjs

GEOBATTLE_TEST_DIST=1 GEOBATTLE_TEST_SECTION=smoke node tests/browser.mjs
GEOBATTLE_TEST_DIST=1 GEOBATTLE_TEST_SECTION=responsive node tests/browser.mjs
node tests/offline.mjs
node tests/render-gallery.mjs
node tests/render-cache.mjs
```

基础功能分段报告的站点为 `http://127.0.0.1:4190`，最后生产六视口复核为 `http://127.0.0.1:4197`；脚本默认会自行启动 `127.0.0.1:4178`。复用已经启动的服务器时设置 `GEOBATTLE_EXTERNAL_SERVER=1` 和正确的 `GEOBATTLE_TEST_URL`。使用预置 QA 运行时时可以设置 `PLAYWRIGHT_MODULE` 与 `PLAYWRIGHT_EXECUTABLE`；这些是测试环境配置，不是产品运行依赖。`GEOBATTLE_TEST_DIST=1` 配合默认 all 选择生产 smoke，显式选择 responsive 可执行生产六视口。基础完整 68 项与最后生产复核范围分开记录。

最终性能和长测命令：

```bash
GEOBATTLE_TEST_DIST=1 PERF_SECONDS=12 node tests/performance.mjs

GEOBATTLE_TEST_DIST=1 PERF_SCENE=none GEOBATTLE_LONGRUN=1 LONGRUN_SPEED=4 LONGRUN_QUALITY=auto node tests/performance.mjs
```

完整性能输出为 `evidence/browser-performance.json`；每次修复/控制前后都应单独保存证据，避免后续覆盖旧结果。只跑长测时输出 `evidence/browser-longrun.json`。`PERF_SCENE` 还可选择 `1-vs-1`、`10-vs-10`、`100-vs-100`、`300-vs-300`、`500-vs-500`、`600-vs-600`、`extreme-effects`，单场输出为 `evidence/performance-场景名.json`。`PERF_SECONDS` 最小 2 秒；长测默认至少 180 秒墙钟、累计 180 秒模拟、首局之外至少 3 次完整自然结束的重赛，默认最多等待 360 秒。降低时长参数不会绕过最低 180 秒门槛；只选择 `none` 而未启用长测会明确拒绝，不能产生空的成功报告。`LONGRUN_QUALITY` 允许 auto/high/medium/low，本轮最终长测与完整矩阵均采用 auto；该选项不改游戏逻辑。

诊断命令采用相同 `PERF_SCENE=100-vs-100 GEOBATTLE_TEST_DIST=1 node tests/performance.mjs`，分别额外设置 `GEOBATTLE_QA_SOFTWARE_CANVAS=1`、`GEOBATTLE_QA_SYNCHRONIZED_CANVAS=1`、`GEOBATTLE_QA_CPU_BACKING=1`。三者依次为浏览器启动增加 `--disable-accelerated-2d-canvas`、测试注入 `desynchronized:false`、测试注入 `willReadFrequently:true`。诊断后产品采用读取偏好 hint，并进一步以同步呈现处理了异步呈现兼容问题；**最终矩阵与长测不设置这三个 QA 控制变量，也不要求用户手动加浏览器启动参数**。实际开关状态与 context 属性同时写入 JSON，不能仅用 WebGL renderer 字符串推断 Canvas 2D 路径。

两个 render 脚本由已执行的独立渲染验证脚本整理而来，归档后只做语法核对，没有再次运行并重复计数。Node 纯模拟性能数据来自一次独立内联基准，JSON 保留编队、种子、布局、步数与每 tick 样本；本节没有把浏览器性能命令冒称为该原生基准的执行入口。

### 3.2 战斗规则与 36 兵种真实性

`tests/simulation.test.js` 对 35 种具有攻击能力的预设单位分别执行真实自动对战：单位从实际编队开始，经过寻敌、移动、攻击/技能与事件结算直至引擎自然给出结果。每种必须产生实际伤害；定义主动招牌技能的单位必须记录真实技能使用；各场核对有限状态和统计守恒。治疗师另外验证主动寻找受伤友军、产生真实治疗、生命上限、排除死亡/自身/诱饵目标。不是给 36 张卡片各写一个“定义存在”的测试。

| 机制 | 实际验证 |
| --- | --- |
| 1 对 1 与悬殊规模 | 单位实际接近并多次攻击、伤亡守恒；100 农民对 1 巨人能够结束、发生大量真实死亡并回收尸体；自爆鸡会通过真实死亡链结算 |

## 6. 性能方法和实测数据

### 6.1 指标定义

以下定义直接对应 `tests/performance.mjs` 与 controller 的原始计数，不使用截图耗时估算 FPS：

- **平均 FPS**：`1000 / 所有有效 RAF 间隔的算术平均毫秒数`。使用未封顶的 RAF 时间戳差，不把 controller 的 100 ms 墙钟接纳上限应用到统计间隔。第一个观察回调尚无前一个时间戳，其 gap 为 null；完整墙钟时长仍包含等待第一帧的时间，因此 FPS 间隔覆盖时长与完整墙钟窗口可能不同。
- **1% low FPS**：将间隔从小到大排序，取最慢约 1% 间隔的平均，再计算 `1000 / 该平均毫秒数`；不是最快 99% 的平均，也不是最小单帧的倒数。
- **平均 tick CPU**：`全部采样帧内 Simulation.step 总 CPU 毫秒 / 实际执行 tick 总数`。`lastFrameSteps` 为本帧 tick 数，`lastFrameStepMs` 为本帧所有 step 的总耗时；不会对 HUD 平滑值再平均，也不会让没有执行 tick 的渲染帧降低这个平均值。
- **平均 draw CPU**：每次实际绘制调用的同步 CPU 耗时均值，不包含后续异步合成或软件 GPU 的完整成本。
- **实际模拟速度**：`整段模拟时间增量 / 整段实际墙钟秒数`。HUD 的最后一个约 0.5 秒窗口另以 `hudLatestWindowSpeed` 保存，不能拿末窗代替全程。
- **长帧与样本**：保留 startup、全部已观察原始 RAF 间隔、最大间隔、超过 250 ms 次数和原始样本。没有为提高平均数删除 outlier 或 warmup。长测检查点间的观察间隙单独标注，不伪装成连续逐帧采样。

场景请求 1×，每段目标采样 12 秒；若自然结束则立即停在结束位置，不把静止结果对话框混入 FPS。报告保存实际墙钟、模拟秒数、起止人数和弹丸峰值，读者能判断军队自然死亡后负载下降的影响。

主循环固定 `1/60` 秒步进，每 RAF 约 10 ms 模拟 CPU 预算、最多 120 步，未消费的模拟 accumulator 保留。每帧最多把 100 ms 墙钟时间乘请求倍速加入 accumulator，避免恢复时无限追赶；超长墙钟空洞因此可能使实际速度低于请求值。游戏通过实际速度读数披露这种情况，性能报告用完整未裁减的墙钟时间计算，不以接纳上限修饰速度。

**性能脚本的 `passed` 是采样、无错误、有限状态与真实推进门禁，不是“所有场景达到 60 FPS”的自动认证。** 本节的目标比较必须逐行依据真实帧率另外判断；未达目标会写明。

### 6.6 1200 上限的解释

全场 1200 是技术保护上限，红蓝共享且包括召唤物。编辑、随机、导入和召唤遵循同一规则；非法新增被拒绝或抑制，不删除已有单位、不改变兵种数值。600 / 1000 附近给出负载提示，默认打开为 80 人。

依据包括 1200 活动实体容量测试、10 模拟秒的 1200 农民纯模拟、1200 几何对象缓存检查，以及最终混编 600 对 600 浏览器观察：1200 初始实体真实推进 458 tick / 7.633 模拟秒，结束 813 活动实体，数值全部有限；平均 12.05 FPS、1% low 5.713 FPS、实际 0.636×。这些结果证明受保护的该数量能够运行，**不能证明 1200 单位浏览器流畅**，也不是任意军阵、低端设备、4× 高特效或长时间满负载的保证。容量上限没有为掩盖性能未达而被改写为体验推荐数。

## 7. 最终连续运行、自然重赛与内存

### 7.1 长测方法与通过条件

最终证据为 [browser-longrun.json](../evidence/browser-longrun.json)，记录开始 `2026-10-12T15:23:49.460Z`，最后堆采样 `2026-10-12T15:26:50.181Z`。长测通过产品自己的 RAF 主循环运行 100 对 100 的剑士、步枪、火法、自爆鸡混编，种子 99331；请求 4×、auto，主 Canvas 实际为同步呈现、读取偏好 true，三个 QA 控制开关全部 false。没有增加禁用 Canvas 加速参数、减少单位 HP、缩短战斗最大时限、直接设置结果或由测试热循环调用 `sim.step()`。

门禁必须同时满足：墙钟至少 180 秒；跨重赛累计真实模拟至少 180 秒；首局之外至少 3 局完整自然结束的重赛；每次同种子完整结果一致；页面保持可见、没有暂停或错误模式；观察到的实体/弹丸关键值有限；没有页面错误或连续观察到 5 秒无模拟正向进展。默认最大 360 秒到达但其它条件不足时失败。15 秒检查点或墙钟到点本身不构成成功。

结束由引擎自然给出 FINISHED 与结果，再调用产品正常重赛入口。脚本以 `JSON.stringify(sim.result)` 比较每一份完整结果，不只比较胜方；只有自然完成才累计完成重赛。每个约 15 秒检查点记录真实墙钟、累计/本段模拟秒、全程/末窗速度、完整结果数、重赛启动数、实体/弹丸/特效与池大小、原始 RAF 和有限性。observer 段间暂停期间，产品仍继续运行；边界间隙以 `checkpointBoundaryGapMs` 保留，包含 I/O/CDP 采样影响，不能称为连续每个游戏帧均被观察。

5 秒推进门禁检查观察到的正向增量，不等于保证没有超过 5 秒的 RAF 空洞：长空洞后若已有正向增量，进度时标会刷新。因此原始最大间隔仍独立披露。本次观察最大间隔为 983.2 ms，没有通过该检查的文字描述隐藏停顿。

## 10. 已知边界与不作出的保证

1. **设备范围。** 已执行浏览器为上述 Linux headless Chromium + SwiftShader。Firefox、Safari、Windows 实体 GPU、真实 Android/iOS、实体高 DPR/4K 设备尚未单独验收。六 CSS 视口不扩大这一范围。
2. **容量与速度。** 1200 是活动实体保护上限，不是普遍推荐规模。最终可见构建七场平均仅 10.92～12.63 FPS，全程实际 0.589～0.868×，60/30 FPS 目标未达到。180 秒长测功能通过，但请求 4× 只达到 2.867×，不能据此宣布性能问题解决。默认 80 人用于打开即玩，不用少量 CPU 耗时推断网页流畅度。
3. **模拟物理。** 圆形软碰撞、有限分离与冲量表达拥挤和重物，不提供通用刚体精度。密集团队会短暂压挤；地图无障碍，因此不实现 A* 或复杂寻路。无人机/飞碟的悬浮不造成永久无法命中。
4. **确定性。** 相同构建、运行环境、编队与种子已验证核心复现；不承诺不同浏览器或 CPU 架构浮点状态逐字节一致。新种子不保证改变胜方，悬殊战斗仍可能同样结束。
5. **规则边界。** 残留攻击允许死亡来源继续归属，召唤物按寿命继续；硬控窗口和恢复保护有上限，但多种敌人先后控制仍可形成压力。有限覆盖测试不能证明所有任意输入组合都不存在缺陷。
6. **存储与离线。** 浏览器 localStorage 与当前地址/配置绑定，不云同步。`file:` 地址的存储策略依浏览器而异；导出 JSON 是迁移方式。被禁用/损坏/写满会提示，仍可内存游玩。源码构建首次安装可能需要网络，已经构建的单 HTML 不需要。
7. **内存。** 复用、回收和数量边界有代码与测试；本轮 CDP usedSize 从 3,720,136 增至 18,773,208 字节，间中有回落。数分钟观察既不能证明无泄漏，也不能直接把全部增长定性为泄漏；未覆盖所有浏览器资源。
8. **可访问性与声音。** 控件具有语义和焦点状态；Canvas 战场没有完整的屏幕阅读器替代操作模式。合成音频的节点/静音/限频经过检查，未做实体扬声器主观听感评估。
9. **平衡。** 遵循任务书的娱乐沙盒差异，不宣称 36 单位竞技公平。没有隐藏时代克制、阵营补偿、人数作弊或为演示胜负调参。
10. **交付核对。** 源包已做独立 CRC、路径、必需文件、解压运行和生产散列核对；文档冻结后的最终清单与压缩包自身校验独立记录在交付环节。打包通过不会改变性能验收结论，不能借用中间不可见呈现版本的较高帧率作为当前产品表现。

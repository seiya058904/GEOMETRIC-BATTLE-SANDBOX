# V2 性能后续：1200人栅格修复与550ms异常复查

2026-10-13，Asia/Shanghai。基于本地9f964f361a16e9467fc38ffd9865bef0b15bec17；初始工作树干净。

**本轮完成低画质图块的透明边距裁剪，当前实际AMD后端1200人三轮平均58.56FPS。历史软件300v300的550ms长帧没有重现，确切触发未确认，不能宣称已根治。** 两项状态分别报告，原失败仍保留。

## 不变量与修改范围

生产源码仅修改src/render/renderer.js：缓存128×128几何图块创建时扫描alpha，保留所有非零alpha像素和两像素过滤边距；drawImage使用紧致源矩形及对应原始坐标。**分辨率仍128px、16像素/单位半径**，不是缩小图块或删除士兵。既有两种攻击姿态、真实位置/朝向/体型/击退/空中状态/受击/血条与选中完整几何仍保留。每种type/team/pose只读一次像素，每帧不readback。

控制器、模拟全部文件、单位数据、胜负、1200上限、固定tick、RAF计时与100ms截断均未修改。新增纯alpha边界回归、真实浏览器像素对照，以及测试专用CPUprofile/场景trace/诊断控制和指定编队自然长测。诊断覆盖只在PERF_RENDER_PROBE显式启用，默认验收无覆盖。

## 复现与历史边界

旧失败evidence/v2/performance-after-run-2.json：300v300一场19.50FPS、0.733×、最长550ms；同时有221/462ms draw和198ms step耗时突增，不能单从这些数值判定GC、栅格同步或OS调度。旧AMD三轮600v60028.33FPS资料也保持原样。

先冻结9f964f3源码（perf-followup/baseline-source.zip），分别跑软件300、硬件600独立冷启动各三次，再按旧七场顺序、每后端三冷浏览器跑完整基线。当前**未修改的基线**软件300三轮42.36FPS、0.9996×、最长66.7ms；AMD600为37.20FPS，已超过30。旧19.50/28.33不得作为这次代码增益的直接分母。两次测量时段不同，当前结果不能反推旧失败由外部干扰造成；历史窗口有限父代理工具元数据也不能证明系统无其他负载。

本补丁只作用于已有low图块路径；300v300默认初始medium、之后high，不走该分支。因此其42.36→43.06的小差异不宣称优化效果，也不作为550ms已修复的证明。旧异常继续标NEEDS-VERIFICATION；若再次出现，需要同一次同步trace才能定位确切阻塞。

## 剖析和单变量控制

Windows、Ryzen7 9700X/16逻辑CPU、约31.61GiB宿主内存、Chromium151.0.7922.34、Playwright1.62.1。软件强制ANGLE SwiftShader；硬件明确D3D11/enable-gpu，WebGL与CDP SystemInfo每场冷浏览器核实AMD RX7900XT，driver31.0.24033.1003、compositing/rasterization enabled。实际GPU后端不等于主Canvas全在GPU绘制：保留willReadFrequently:true偏好，Canvas后台位置不能从hint断言。

目标12秒trace/CPUprofile：before native每次Blink.Paint.UpdateTime平均约23.0ms（392次），after约9.35ms（708次），最长38.12→12.75ms；两次都是同样instrumentation的独立600v600。GPU Flush包含时长总量没有对应的大幅下降。瓶颈证据指向Canvas延迟Paint阶段的旋转位图栅格成本，而不只JS提交或模拟AI。Paint嵌套事件会重叠，不能把包含时长相加当CPU百分比；剖析运行不并入正式均值。

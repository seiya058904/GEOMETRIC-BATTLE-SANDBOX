# V2 真实性能调查

## 方法与边界

修前基线取自 `evidence/v2/baseline-source`（Git archive 924150f），通过独立4180端口运行，避免并行源代码修改污染样本。修前与修后均使用 `tests/v2-performance.mjs`：同七个原有固定编队与种子、1920×1080、DPR1、auto画质、请求1×、每场12秒墙钟、每矩阵三次。每次冷启动浏览器，矩阵内保持原场景顺序；自然结束立即停止，不把静止战报算入FPS。测试窗口由主代理协调，禁止同时运行其他浏览器测试。

环境为 Windows win32 / 无头 Chromium / 强制ANGLE SwiftShader，不代表实体Windows显卡或真机Android。原始JSON记录CPU、RAM、浏览器版本、实际Canvas属性、完整RAF样本。平均FPS=1000/平均RAF间隔，1%low采用最慢1%间隔的平均倒数；p95/p99和最长间隔保留启动及异常帧。step平均为累计实测step工作/真实tick数量；p95FrameMeanStepMs是每帧平均tick耗时的p95，**不是单tickp95**。JS draw耗时不含异步raster/compositor。

可见性检查在计时窗口之后独立重启同场景，两个相隔500ms的合成截图，记录模拟位置和时钟变化，并解码PNG检查主战場中央确有红蓝像素及画面变化，防止Canvas内部命令成功但呈现为空。旧截图原始RAF样本未修改，只补充截图像素验证字段。

运行命令（设置可用PLAYWRIGHT_MODULE后）：

```powershell
$env:GEOBATTLE_TEST_URL="http://127.0.0.1:4180"
$env:GEOBATTLE_EXTERNAL_SERVER="1"
$env:PERF_PHASE="before"
node tests/v2-performance.mjs
```

## 控制实验与定位

每次仅改主Canvas的一项属性，启动参数不变，同1v1种子、12秒采样，保留结果和截图；这些单次诊断不能当作完整矩阵加速比。

|变量|FPS|速度|像素可见|决策|
|---|---:|---:|---|---|
|cpu-false|23.59|0.978×|通过|没有实质收益，暂保留既有读取偏好|
|desync-true|59.75|1.004×|失败|**拒绝**：主战场为空白，属于性能假通过|
|alpha-true|27.73|0.990×|通过|可见且单次较快，需复测完整负载后才能采用|
|profile-default|24.12|0.984×|通过|只用于剖析，不并入验收均值|

默认context为alpha:false/desynchronized:false/willReadFrequently:true。desynchronized:true虽达到59.75FPS、state/drawnUnits亦正常，却在合成截图中没有士兵与棋盘；因此保留其失败JSON与PNG，而不以59.75FPS宣传成功。

CDP原始trace：`evidence/v2/performance-trace-default.json`，摘要 `performance-trace-summary.json`。CrGpuMain中 `RasterDecoderImpl::DoEndRasterCHROMIUM::Flush` 包含时长合计约13.4秒，单次最长174.8ms；1v1 JS draw均值仅0.118ms、step均值0.037ms。这支持当前瓶颈集中在SwiftShader栅格/呈现路径，而不是单位AI或空间网格。**包含时长会互相重叠，不可相加当CPU占比。** 该诊断包含截图观察段，trace有开销，不能并入正式矩阵。

因此没有为性能改兵种数值、单位人数、模拟固定步长、胜负、AI或碰撞，也没有盲目引入Worker/GPU重写。主Canvas保持同步呈现，拒绝高FPS空白帧方案。编辑器原有冻结编队帧缓存、背景点阵pattern缓存和low画质单位图块均保留。

## 180秒自然重赛（SwiftShader）

原始 `evidence/v2/performance-longrun.json`，请求1×/auto，全程自然RAF推进，没有手动step、强制结束、清累积或改速度。真实墙钟181.408秒，累计模拟180.000秒（0.992×）；9局自然完成，首局之外8次完成重赛。每局1172tick/19.5333模拟秒。运行时逐局将完整sim.result做JSON.stringify比较，8次完整结果比较均一致，未只比较胜方；原始results保存紧凑的各局摘要，验证代码保留完整JSON比较与失败分支。页面错误0、非有限状态0、非法模式0、冻结失败0。

观察段内RAF最大150ms；包含CDP/Windows进程/截图检查点的观察边界最大1416.7ms，边界来自探针暂停观察，不可称游戏长帧。模拟在检查点仍推进，所以保留全墙钟及实际速度，不把这些时间排除。12个PNG检查点两队像素均可见。

CDP堆检查点4.10–16.13MiB，起点到终点增加12.07MiB；无强制GC，堆曾多次回落，不能据此证明无泄漏。DOM节点702–3150、事件监听30–89，之后下降至974/56；未观察到持续单调增长，但180秒不能证明长期稳定。项目池、单位与模拟状态有限。Windows对本Chromium进程组的WorkingSet合计594.95–676.36MiB，PrivateMemory453.34–511.59MiB；CPU累计增量245.19秒，约1.35个CPU核心当量（不是主线程单核或真实GPU占用率）。原始每进程PID/CPU/内存、CDP GPU CPUtime原值和每段池数量均保留，不混同为宿主机可用内存。

## 交互延迟与剩余边界

最终1200部署压力的7个可信输入测得6–310.4ms（主代理真实输入报告）。本任务没有修前同口径延迟组，不宣称延迟前后改善。Native完整矩阵没有另包每tick诊断，nativep95FrameMeanStepMs只能读作帧内平均tick耗时分位数；逐tick真实p95补充表来自SwiftShader两组。物理显示屏下完整手工FPS/音效体验、安卓真机均未测；180秒长测来自软件后端，不冒称native180秒长测通过。
